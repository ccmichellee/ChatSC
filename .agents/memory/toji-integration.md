---
name: ChatSC recommendation agent
description: Product positioning and safety boundaries for the student recommendation agent
---

ChatSC's core product turns scattered USC events, student-run clubs and
communities, official campus resources, internships, and opportunities into
personalized, actionable recommendations, primarily delivered by an AI agent
over text. The website is the onboarding and discovery interface. Keep student
organizations distinct from official campus services, while making both
discoverable. Do not use the retired Toji brand or position ChatSC mainly as a
between-classes guide.

**Why:** The user clarified that the AI texting agent is the main product and the
website is its interface. Text delivery is not currently connected in the preview.

**How to apply:** Keep messaging delivery and shared conversation memory in the
existing Python agent. In the website, present clubs and official resources as
distinct content types; link resource summaries to official USC sources. Never
imply messages are being sent until delivery is connected. Do not treat a typed
phone number as verification or permission to reveal a profile; preserve
explicit messaging consent before enabling texts.

Students sign up on the website to receive personalized text recommendations;
they do not initiate signup by texting a keyword or short code. Do not include
an interactive preview-text or iMessage-demo feature. A static phone image on
the homepage is acceptable, but it does not send real SMS.

**Why:** The user chose website signup and text recommendations as the product
message, while specifying that this change is wording only, not SMS activation.
They subsequently explicitly requested removal of the preview-text demo feature.

**How to apply:** Do not reintroduce short-code placeholders or instructions to
text first or add a demo flow after signup. Real text delivery requires a
connection and explicit student opt-in.
