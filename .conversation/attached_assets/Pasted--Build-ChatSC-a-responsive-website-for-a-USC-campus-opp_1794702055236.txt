
Build "ChatSC", a responsive website for a USC campus opportunity finder, on top of the EXISTING Python code in this repo. Read the repo first. Do not rewrite or delete existing files. Add a web layer next to them.

CONTEXT (existing code)
- student_memory.py: MemoryStore, a SQLite store (memory.db) with students, events, clubs, and sent_recommendations. Read it first and use its real methods (upsert_event, add_club, search_events, search_clubs, get_student_profile, save_student_profile, get_unnotified_events_for_student, etc.).
- crawl_usc_events.py: crawl_events() pulls from the calendar.usc.edu API and the EngageSC API into memory.db.
- scrape_usc_clubs.py: crawls EngageSC clubs into memory.db.
- seed_memory.py: fallback demo data.
- bot.py, imessage_reader.py, imessage_sender.py: macOS-only iMessage bot. Do NOT run or import these on Replit. Leave them untouched.
- llm_client.py: Meta API agent. The website must work with NO API key.

STACK
- Backend: Python FastAPI (or Flask) in /web/api, importing MemoryStore and the crawlers directly.
- Frontend: React + Vite + Tailwind in /web/frontend, proxying /api to the backend.
- No login. No secrets required.

STYLE
USC-inspired: cardinal red #990000 primary, #EFEEE7 background, gold #FFCC00 accent. Rounded cards, mobile-first, sticky top nav, accessible (semantic HTML, keyboard navigation, strong contrast).

API (read from memory.db)
- GET /api/events (query: q, tag, from, to, free_food)
- GET /api/clubs (query: q, category)
- GET /api/opportunities (static /data/opportunities.json, 12 clearly fictional internships/research/volunteer/job entries, since there is no crawler for these)
- POST /api/onboarding saves phone, consent, interests, availability blocks, and frequency via save_student_profile
- GET /api/recommendations?user=... uses the existing matching and skips conflicts with the user's class blocks
- POST /api/refresh runs crawl_events(days=30, max_pages=2). If the network fails, fall back to seed_memory.seed_database() and never crash.
- Parse the free-form date_str fields into real start/end datetimes where possible. Events that can't be parsed still show in the list but not on the calendar or conflict check.
- Never invent deadlines, locations, or requirements. Show the source (USC Calendar or EngageSC) and last-updated time on every event card.
- Sample opportunities and any fallback data carry the visible label "Sample data" in the UI.

PAGES (top nav)
1. Home: hero "Find clubs, events, and opportunities that fit your interests and your class schedule", a "Get started" button, the next 3 events, and a "Recommended for you" row after onboarding.
2. Events: search, tag filter, date range, and a free-food toggle. Cards show title, host, date/time, location, tags, and a "Remind me" button (UI only, with a toast). Clicking opens a detail modal with source link and timestamp.
3. Map: Leaflet + OpenStreetMap centered on (34.0224, -118.2851). Place markers by matching location text against a small lookup of USC buildings (Leavey, Doheny, Ginsburg, TCC, Bovard, Epstein Plaza, Fertitta, etc.). Events with no known building go in a "Location TBD" list instead of a marker. Sidebar synced with the map and the same filters.
4. Calendar: month and week views (FullCalendar), color-coded by category. "My availability" lets users enter weekly class blocks, conflicting events turn a warning color, plus a "Hide conflicting events" checkbox.
5. Clubs: card grid from /api/clubs with search and category filter, mission text, meeting info, and a "Learn more" link.
6. Opportunities: type filter, sort by deadline, deadlines within 7 days highlighted, "Apply" link.
7. Onboarding (3 steps, progress bar, under 2 minutes):
   - Step 1: phone number with a placeholder "Verify" button (no real SMS) and a consent checkbox: "I agree to receive texts. Reply STOP anytime to unsubscribe."
